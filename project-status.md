# Исходное состояние проекта и актуализация ТЗ

## Состояние технического задания
Техническое задание было повторно проверено и актуализировано под рамки реализации мини-проекта за один семестр. В документ внесены следующие ключевые изменения:

1. **Сокращение платформ (A.01, A.02):** Исключена разработка под iOS и кроссплатформенная модель. Приложение будет разрабатываться исключительно под платформу Android как полностью локальное (автономное) решение.
2. **Упрощение базы данных (F.01.04, C.02, D.01):** Из требований полностью удалена СУБД Oracle SQL Developer. Хранение данных переведено на локальную реляционную базу данных SQLite (с использованием библиотеки Room).
3. **Изменение типа уведомлений (F.03.01):** Архитектурно сложные Push-уведомления (требующие внешнего сервера) заменены на локальные уведомления на устройстве, работающие через системный планировщик Android.
4. **Удаление избыточных функций (F.03, F.04 в старой редакции):** Полностью исключены функции «Совместное использование» (разделение счета между участниками) и «Поиск более дешевых альтернатив» как неотносящиеся к базовой функциональности MVP.
5. **Упрощение экспорта (C.03):** Из требований к выгрузке отчетов удален тяжелый формат PDF. Оставлен только экспорт в текстовый формат CSV.
6. **Оптимизация безопасности (S.01):** Удалено требование по реализации авторизации через PIN-код и биометрию (TouchID/FaceID). Вместо этого фокус смещен на изоляцию файла БД внутри системной песочницы приложения.
7. **Инструменты проектирования (Этап 1):** Конструктор сайтов Tilda заменен на графический редактор Figma для проектирования интерфейса. Вместо SQL Developer для локальной отладки схем утвержден DB Browser for SQLite.

## Текущее состояние проекта
* **Репозиторий проекта:** Создан на GitHub.
* **Архитектура и ТЗ:** ТЗ успешно скорректировано, зафиксированы итоговые рамки разработки.
* **Диаграммы:** Имеются базовые UML-диаграммы с прошлого семестра (требуют точечной актуализации под новое ТЗ на следующей неделе).
* **Программная реализация:** Программный код приложения и структура локальной базы данных на данный момент полностью отсутствуют.

## Актуализация UML-диаграмм (Неделя 2)
В связи с оптимизацией технического задания на Неделе 1, ранее подготовленная диаграмма вариантов использования (Use Case) была скорректирована для исключения избыточной функциональности. 
**Внесенные изменения на диаграмме:**
1. **Исключен блок «Семейные подписки»**: полностью удалены варианты использования «Выбирает подписку с типом семейная», «Добавляет участников в группу» и «Указание доли оплаты участников».
2. **Исключены функции уведомлений о задолженностях внутри группы**: удалены прецеденты «Уведомление главе группы о неоплате...», «Отправка сообщения участникам семейной подписки об оплате» и «Пометка должника красным цветом».
3. **Удален блок «Контроль цен и неиспользуемых сервисов»**: стерты прецеденты «Выдача уведомления о подорожании сервиса», «Проверка, подорожала ли цена...», «Отправление уведомления о неиспользуемой подписке...», «Выбор проблемной подписки на главной странице» и «Выбор: остановить подписку или удалить».
4. **Скорректирован прецедент «Отправка предупреждения за 24 часа...»**: теперь данное действие инициируется исключительно локальной Системой (планировщиком Android) без участия внешних бэкенд-серверов.

## Декомпозиция функциональности на задачи разработки (Неделя 2)

### Блок 1. Проектирование и дизайн интерфейса ( Figma )
* **Задача 1.1:** Разработка интерактивных макетов экранов приложения.
  * *Ожидаемый результат:* Готовый проект в Figma, включающий макет главного экрана, экрана со списком подписок, формы добавления/редактирования и экрана аналитики.
  * *Зависимости:* Нет.
  * *Статус:* В работе.
* **Задача 1.2:** Проектирование цветовых схем для светлой и темной тем оформления.
  * *Ожидаемый результат:* Зафиксированная палитра цветов (включая маркеры близости даты списания) в дизайн-системе проекта.
  * *Зависимости:* Задача 1.1.
  * *Статус:* В планах.

### Блок 2. Слой хранения данных ( SQLite / Room )
* **Задача 2.1:** Проектирование физической схемы базы данных в DB Browser for SQLite.
  * *Ожидаемый результат:* Файл схемы БД, описывающий таблицы подписок (`Subscriptions`) и категорий (`Categories`) с правилами внешних ключей.
  * *Зависимости:* Нет.
  * *Статус:* В планах.
* **Задача 2.2:** Программное описание сущностей и создание БД через Room.
  * *Ожидаемый результат:* Кодовая база Android-приложения с классами `@Entity`, интерфейсами `@Dao` и основным классом `AppDatabase`.
  * *Зависимости:* Задача 2.1.
  * *Статус:* В планах.
* **Задача 2.3:** Настройка механизмов начальной миграции и создание локального списка шаблонов.
  * *Ожидаемый результат:* Скрипт автоматического заполнения таблицы популярных сервисов (Яндекс Плюс и др.) при первом запуске приложения.
  * *Зависимости:* Задача 2.2.
  * *Статус:* В планах.

### Блок 3. Сетевой слой и бизнес-логика ( HTTP / Retrofit )
* **Задача 3.1:** Реализация сетевого клиента для связи с API Центробанка РФ.
  * *Ожидаемый результат:* Настроенная библиотека Retrofit и интерфейс запроса для получения актуальных курсов валют в формате JSON.
  * *Зависимости:* Нет.
  * *Статус:* В планах.
* **Задача 3.2:** Создание класса-репозитория и логики кэширования валют.
  * *Ожидаемый результат:* Реализованный `Repository Pattern`, который отдает данные из сети или локального кэша в случае отсутствия интернета.
  * *Зависимости:* Задача 2.2, Задача 3.1.
  * *Статус:* В планах.
* **Задача 3.3:** Разработка математического модуля конвертации и подсчета баланса.
  * *Ожидаемый результат:* Протестированные алгоритмы автоматического пересчета валютных подписок в рубли и вычисления общей суммы трат за месяц и год.
  * *Зависимости:* Задача 3.2.
  * *Статус:* В планах.

### Блок 4. Верстка пользовательского интерфейса
* **Задача 4.1:** Верстка главного экрана с финансовой аналитикой.
  * *Ожидаемый результат:* Экран с крупным шрифтом баланса и кастомным UI-компонентом (круговая диаграмма по категориям).
  * *Зависимости:* Блок 1, Задача 3.3.
  * *Статус:* В планах.
* **Задача 4.2:** Верстка списков и карточек управления подписками.
  * *Ожидаемый результат:* Интерактивный список подписок с цветовой индикацией сроков оплаты. Реализованные формы добавления (с автоподстановкой параметров) и удаления записей.
  * *Зависимости:* Блок 1, Задача 2.2.
  * *Статус:* В планах.

### Блок 5. Фоновые процессы и уведомления ( WorkManager )
* **Задача 5.1:** Настройка фонового планировщика для контроля дат платежей.
  * *Ожидаемый результат:* Зарегистрированная фоновая задача в WorkManager, ежедневно сверяющая текущую дату со сроками списаний из БД.
  * *Зависимости:* Задача 2.2.
  * *Статус:* В планах.
* **Задача 5.2:** Реализация модуля вывода локальных уведомлений на устройстве.
  * *Ожидаемый результат:* Программный код, создающий системное напоминание на экране смартфона за 24 часа до даты платежа.
  * *Зависимости:* Задача 5.1.
  * *Статус:* В планах.

### Блок 6. Экспорт данных
* **Задача 6.1:** Реализация функции выгрузки отчетов в формат CSV.
  * *Ожидаемый результат:* Метод, генерирующий текстовый файл со списком трат, разделенный запятыми, и сохраняющий его в локальную память телефона.
  * *Зависимости:* Задача 2.2.
  * *Статус:* В планах.
